## 问题是什么？

给你一个数组，里面有一些数字，其中有一个数字出现的次数超过了数组长度的一半（我们称之为"多数元素"）。请你找出这个数字。

举个例子，假设有一个数组 `[2,2,1,1,1,2,2]`：
- 这个数组的长度是7
- 数字2出现了4次，超过了7的一半（一半是3.5次）
- 所以2就是我们要找的多数元素

**简单示例：**
```
输入：[3,2,3]
输出：3  （因为3出现了2次，超过了数组长度3的一半）
```

```
输入：[2,2,1,1,1,2,2]
输出：2  （因为2出现了4次，超过了数组长度7的一半）
```

## 怎么解决这个问题？

有很多方法可以解决这个问题，但今天我们要学习一种又快又省空间的方法——**摩尔投票算法**。

### 摩尔投票算法是什么？

想象一下有两支军队在打仗：
- 红军（代表多数元素）
- 蓝军（代表所有其他元素）

由于红军人数超过总人数的一半，所以即使红蓝双方一对一厮杀（相互抵消），最后战场上剩下的一定是红军！

这就是摩尔投票算法的核心思想：**不同的数字相互抵消，最后剩下的一定是出现次数最多的那个数字**。

### 算法步骤（超简单版）

1. 找一个"候选人"，先认为第一个数字是候选人
2. 开始计数：遇到和候选人一样的数字就+1，遇到不一样的就-1
3. 如果计数变成0了，就换一个候选人（选当前遇到的那个数字）
4. 继续上面的过程直到结束
5. 最后的候选人就是我们要找的多数元素

## 代码怎么写？

### 旧代码（有点复杂）

原来的代码有点复杂：

```go
func majorityElement(nums []int) int {
	cnt := 0
	num := -1

	for i := range nums {
		if num == -1 {
			cnt = 1
			num = nums[i]
			continue
		}

		if nums[i] == num {
			cnt++
			continue
		}
		cnt--
		if cnt == 0 {
			num = -1
		}
	}

	cnt = 0
	for _, n := range nums {
		if n == num {
			cnt++
		}
	}

	if cnt > len(nums)/2 {
		return num
	}

	return -1
}
```

这个代码有点绕，而且做了一些不必要的事情。

### 新代码（简单直观）

我们来看看更简单的写法：

```go
func majorityElement(nums []int) int {
    // 1. 选第一个数字作为候选人
    候选人 := nums[0]
    
    // 2. 候选人的初始票数为1
    票数 := 1
    
    // 3. 从第二个数字开始统计
    for i := 1; i < len(nums); i++ {
        // 如果当前票数为0，换新候选人
        if 票数 == 0 {
            候选人 = nums[i]
            票数 = 1
            continue
        }
        
        // 如果遇到和候选人一样的数字，票数+1
        if nums[i] == 候选人 {
            票数++
        } else {
            // 如果遇到和候选人不一样的数字，票数-1
            票数--
        }
    }
    
    // 4. 最后剩下的候选人就是多数元素
    return 候选人
}
```

用中文变量名可能看起来更直观，但实际代码中我们通常用英文：

```go
func majorityElement(nums []int) int {
    // 1. 选第一个数字作为候选人
    candidate := nums[0]
    
    // 2. 候选人的初始票数为1
    count := 1
    
    // 3. 从第二个数字开始统计
    for i := 1; i < len(nums); i++ {
        // 如果当前票数为0，换新候选人
        if count == 0 {
            candidate = nums[i]
            count = 1
        } else if nums[i] == candidate {
            // 如果遇到和候选人一样的数字，票数+1
            count++
        } else {
            // 如果遇到和候选人不一样的数字，票数-1
            count--
        }
    }
    
    // 4. 最后剩下的候选人就是多数元素
    return candidate
}
```

## 举个例子详细解释

让我们用数组 `[2,2,1,1,1,2,2]` 来一步步看看上面的算法是怎么工作的：

1. 初始状态：
   - 候选人 = 2（第一个元素）
   - 票数 = 1

2. 遍历第2个元素（也是2）：
   - 发现和候选人相同
   - 票数 +1 = 2

3. 遍历第3个元素（是1）：
   - 发现和候选人不同
   - 票数 -1 = 1

4. 遍历第4个元素（是1）：
   - 发现和候选人不同
   - 票数 -1 = 0

5. 遍历第5个元素（是1）：
   - 票数为0，所以换新候选人
   - 候选人 = 1
   - 票数 = 1

6. 遍历第6个元素（是2）：
   - 发现和候选人不同
   - 票数 -1 = 0

7. 遍历第7个元素（是2）：
   - 票数为0，所以换新候选人
   - 候选人 = 2
   - 票数 = 1

8. 遍历结束，最终候选人是2，这就是我们要的答案！

用表格表示更清晰：

| 当前位置 | 当前数字 | 候选人 | 票数 | 操作说明 |
|---------|---------|--------|------|---------|
| 开始     | -       | 2      | 1    | 初始状态，选第一个数为候选人 |
| 位置1    | 2       | 2      | 2    | 遇到相同数字，票数+1 |
| 位置2    | 1       | 2      | 1    | 遇到不同数字，票数-1 |
| 位置3    | 1       | 2      | 0    | 遇到不同数字，票数-1 |
| 位置4    | 1       | 1      | 1    | 票数变为0，换新候选人 |
| 位置5    | 2       | 1      | 0    | 遇到不同数字，票数-1 |
| 位置6    | 2       | 2      | 1    | 票数变为0，换新候选人 |

## 为什么这个算法有效？

因为多数元素出现次数超过了数组长度的一半，所以即使它和其他所有元素一一"对抗"（相互抵消），最后剩下的也必定是它。

就像两支军队打仗：
- 红军（多数元素）有100人
- 蓝军（其他所有元素）合起来最多只有99人
- 即使红蓝双方一对一厮杀，最终也会剩下至少1个红军

## 算法效率

- **时间效率**：只需要遍历数组一遍，所以是O(n)
- **空间效率**：只用了两个变量（候选人和票数），所以是O(1)

## 不同方法比较

虽然有很多方法可以解决这个问题，但摩尔投票算法是最简单高效的：

1. **计数法**：用一个表记录每个数字出现的次数，需要额外空间
2. **排序法**：把数组排序后取中间元素，速度较慢
3. **摩尔投票法**：又快又省空间，是最佳选择！
