## 问题描述

给定一个大小为 n 的数组 nums，返回其中的多数元素。多数元素是指在数组中出现次数 **大于** ⌊ n/2 ⌋ 的元素。

你可以假设数组是非空的，并且给定的数组总是存在多数元素。

**示例 1：**
```
输入：nums = [3,2,3]
输出：3
```

**示例 2：**
```
输入：nums = [2,2,1,1,1,2,2]
输出：2
```

**约束条件：**
- `n == nums.length`
- `1 <= n <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`

## 解题思路

这道题目有多种解法，包括：
1. 哈希表计数
2. 排序后取中间值
3. 分治算法
4. **摩尔投票算法（Boyer-Moore Voting Algorithm）**

其中，摩尔投票算法是最为优雅且高效的解决方案，它利用了多数元素的特性（出现次数超过一半），可以在 O(n) 时间和 O(1) 空间内解决问题。

### 摩尔投票算法原理

摩尔投票算法的核心思想是：
- 如果有多数元素，那么这个元素的出现次数减去其他所有元素的出现次数后，结果仍然大于 0。

算法流程如下：
1. 维护一个**候选元素**和一个**计数器**
2. 遍历数组中的每个元素：
   - 如果计数器为 0，将当前元素设为候选元素，计数器设为 1
   - 如果当前元素等于候选元素，计数器加 1
   - 如果当前元素不等于候选元素，计数器减 1
3. 最终留下的候选元素就是多数元素

这个算法基于"抵消"的概念：将多数元素与其他元素两两抵消，最后剩下的元素一定是多数元素。

## 实现细节

我们来看一下代码实现：

### 初始实现（冗长版）

首先，让我们看一下原始的实现：

```go
func majorityElement(nums []int) int {
	cnt := 0
	num := -1

	for i := range nums {
		if num == -1 {
			cnt = 1
			num = nums[i]
			continue
		}

		if nums[i] == num {
			cnt++
			continue
		}
		cnt--
		if cnt == 0 {
			num = -1
		}
	}

	cnt = 0
	for _, n := range nums {
		if n == num {
			cnt++
		}
	}

	if cnt > len(nums)/2 {
		return num
	}

	return -1
}
```

这个实现有几个问题：
1. 初始化 `num` 为 -1，引入了不必要的特殊情况处理
2. 额外进行了一次验证步骤（题目已保证存在多数元素）
3. 代码冗长，流程不够清晰

### 优化实现（简洁版）

现在，让我们优化这个实现：

```go
func majorityElement(nums []int) int {
    // 初始化候选元素为第一个元素
    candidate := nums[0]
    // 初始化计数器为1
    count := 1
    
    // 从第二个元素开始遍历
    for i := 1; i < len(nums); i++ {
        // 如果计数器为0，更新候选元素
        if count == 0 {
            candidate = nums[i]
            count = 1
        } else if candidate == nums[i] {
            // 如果当前元素等于候选元素，计数器加1
            count++
        } else {
            // 如果当前元素不等于候选元素，计数器减1
            count--
        }
    }
    
    // 由于题目保证存在多数元素，直接返回候选元素
    return candidate
}
```

这个实现更简洁明了：
1. 直接使用第一个元素作为初始候选元素
2. 逻辑清晰，没有不必要的特殊情况处理
3. 去掉了验证步骤（因为题目保证存在多数元素）

## 代码执行示例

让我们以示例 `[2,2,1,1,1,2,2]` 为例，追踪代码执行过程：

| 索引 | 当前元素 | 候选元素 | 计数器 | 操作 |
|------|---------|---------|--------|------|
| 0    | 2       | 2       | 1      | 初始化 |
| 1    | 2       | 2       | 2      | 元素相同，计数器+1 |
| 2    | 1       | 2       | 1      | 元素不同，计数器-1 |
| 3    | 1       | 2       | 0      | 元素不同，计数器-1 |
| 4    | 1       | 1       | 1      | 计数器为0，更新候选元素 |
| 5    | 2       | 1       | 0      | 元素不同，计数器-1 |
| 6    | 2       | 2       | 1      | 计数器为0，更新候选元素 |

最终，候选元素为 2，这就是多数元素。

## 复杂度分析

- **时间复杂度**：$O(n)$，其中 n 是数组的长度。我们只需要遍历数组一次。
- **空间复杂度**：$O(1)$，只需要常数级别的额外空间。

## 方法比较

| 方法 | 时间复杂度 | 空间复杂度 | 优点 | 缺点 |
|------|----------|-----------|------|------|
| 哈希表计数 | $O(n)$ | $O(n)$ | 容易理解和实现 | 需要额外空间 |
| 排序法 | $O(n\log n)$ | $O(1)$ 或 $O(n)$ | 简单直接 | 时间复杂度高 |
| 分治法 | $O(n\log n)$ | $O(\log n)$ | 可以并行化 | 实现复杂 |
| 摩尔投票 | $O(n)$ | $O(1)$ | 时间和空间效率最高 | 仅适用于确定存在多数元素的情况 |

## 关键收获

1. **摩尔投票算法**是解决多数元素问题的最优解，既高效又节省空间。
2. 在算法实现中，应该避免不必要的特殊情况处理和验证步骤，使代码更简洁清晰。
3. 这个问题的延伸可以考虑：如果不保证存在多数元素，如何处理？（需要增加验证步骤）
4. 摩尔投票算法可以扩展应用到查找出现次数超过 n/3 的元素等问题。
