### 问题描述

给定一个包含红色、白色和蓝色、共 `n` 个元素的数组 `nums` ，**原地**对它们进行排序，使得相同颜色的元素相邻，并按照红色、白色、蓝色的顺序排列。

我们使用整数 `0`、 `1` 和 `2` 分别表示红色、白色和蓝色。

你必须在不使用库的sort函数的情况下解决这个问题。

**示例 1：**

```
输入：nums = [2,0,2,1,1,0]
输出：[0,0,1,1,2,2]
```

**示例 2：**

```
输入：nums = [2,0,1]
输出：[0,1,2]
```

**约束条件：**

- `n == nums.length`
- `1 <= n <= 300`
- `nums[i]` 为 `0`、`1` 或 `2`

### 解题思路

这道题的经典解法是使用**双指针**（或者可以说是三指针）。我们维护三个指针：`left`、`right` 和 `current`。

- `left` 指针表示数组中所有 `0` 应该存放的区域的右边界（不含 `left`）。初始时 `left = 0`。
- `right` 指针表示数组中所有 `2` 应该存放的区域的左边界（不含 `right`）。初始时 `right = len(nums) - 1`。
- `current` 指针用于遍历数组，从左到右扫描。初始时 `current = 0`。

遍历数组时，根据 `nums[current]` 的值进行操作：

1.  **如果 `nums[current] == 0`**：
    -   这意味着我们找到了一个红色元素，它应该被放到 `left` 指针指向的位置。
    -   交换 `nums[current]` 和 `nums[left]`。
    -   `left` 指针向右移动一位，因为我们已经将一个 `0` 放置到了正确的位置。
    -   `current` 指针也向右移动一位，继续扫描下一个元素。**注意：** 因为 `current` 左边的元素都已经处理过（要么是0，要么是1），所以从 `left` 换过来的元素不可能是 `2`，一定是 `0` 或 `1`。如果换过来的是 `0`，`left` 增加后，`current` 也增加，下一次迭代 `current` 指向的是之前换过来的元素，如果是0，则再次执行该逻辑；如果是1，则执行 `else if nums[current] == 1` 逻辑。
2.  **如果 `nums[current] == 2`**：
    -   这意味着我们找到了一个蓝色元素，它应该被放到 `right` 指针指向的位置。
    -   交换 `nums[current]` 和 `nums[right]`。
    -   `right` 指针向左移动一位，因为我们已经将一个 `2` 放置到了正确的位置。
    -   **`current` 指针保持不变 (或者说，在下一次循环开始前 `i--` 来抵消循环的 `i++` )。** 这是因为从 `right` 交换过来的元素可能是 `0`、`1` 或 `2`，需要对这个新换过来的元素 `nums[current]` 再次进行判断。
3.  **如果 `nums[current] == 1`**：
    -   这意味着我们找到了一个白色元素，它已经在正确的位置（在 `0` 和 `2` 之间）。
    -   `current` 指针向右移动一位，继续扫描下一个元素。

循环的终止条件是 `current <= right`。当 `current` 超过 `right` 时，表示所有元素都已经被正确地放置。

这种方法只需要遍历一次数组，时间复杂度为 $O(n)$，空间复杂度为 $O(1)$，因为我们是原地排序。

让我们通过一个例子来理解这个过程：`nums = [2,0,2,1,1,0]`

初始状态: `left = 0`, `right = 5`, `current = 0`
`nums = [2, 0, 2, 1, 1, 0]`
         ^              ^
         c              r
         l

1.  `current = 0`, `nums[0] = 2`。 `nums[0]` 与 `nums[5]` 交换。
    `nums = [0, 0, 2, 1, 1, 2]`
             ^           ^
             c           r
             l
    `right` 变为 4。`current` 保持 0 (因为从 `right` 换过来的 `nums[0]` 需要重新判断)。

2.  `current = 0`, `nums[0] = 0`。 `nums[0]` 与 `nums[0]` 交换 (无变化)。
    `nums = [0, 0, 2, 1, 1, 2]`
                ^        ^
                c        r
                l
    `left` 变为 1, `current` 变为 1。

3.  `current = 1`, `nums[1] = 0`。 `nums[1]` 与 `nums[1]` 交换 (无变化)。
    `nums = [0, 0, 2, 1, 1, 2]`
                   ^     ^
                   c     r
                   l
    `left` 变为 2, `current` 变为 2。

4.  `current = 2`, `nums[2] = 2`。 `nums[2]` 与 `nums[4]` 交换。
    `nums = [0, 0, 1, 1, 2, 2]`
                   ^  ^
                   c  r
                   l
    `right` 变为 3。`current` 保持 2。

5.  `current = 2`, `nums[2] = 1`。
    `nums = [0, 0, 1, 1, 2, 2]`
                      ^ ^
                      c r
                      l
    `current` 变为 3。

6.  `current = 3`, `nums[3] = 1`。
    `nums = [0, 0, 1, 1, 2, 2]`
                         ^
                         c,r
                         l
    `current` 变为 4。

7.  `current = 4`, `right = 3`。 `current > right`，循环结束。

最终排序结果: `[0,0,1,1,2,2]`

### 实现细节

代码实现与上述思路一致。使用 `left` 指针跟踪 `0` 的末尾，`right` 指针跟踪 `2` 的开头。`i` (即 `current` 指针) 从头开始遍历数组。

- 当 `nums[i] == 0` 时，将其与 `nums[left]` 交换，然后 `left` 和 `i` 都向右移动。
- 当 `nums[i] == 2` 时，将其与 `nums[right]` 交换，然后 `right` 向左移动。**关键点：** 此时 `i` 不应该立即增加，因为从 `right` 交换过来的元素还没有被检查，所以通过 `i--` 来抵消 `for` 循环的 `i++`，使得下一次迭代仍然检查当前 `i` 位置的元素。
- 当 `nums[i] == 1` 时，`i` 直接向右移动。

### 代码实现

```go
package main

/*
 * @lc app=leetcode.cn id=75 lang=golang
 *
 * [75] 颜色分类
 */

// @lc code=start
func sortColors(nums []int) {
	left, right := 0, len(nums)-1

	// current 指针 i 从 0 开始遍历到 right
	// 当 i > right 时，表示所有元素已经检查完毕
	for i := 0; i <= right; i++ {
		if nums[i] == 0 {
			// 如果当前元素是 0，交换到数组的左边
			nums[i], nums[left] = nums[left], nums[i]
			// left 指针右移
			left++
			// 注意：这里的 i 也会在 for 循环结束时 ++，
			// 因为换过来的 nums[left] 一定是 0 或 1（因为 left 左边都是0，nums[i]是0，所以 left 位置不可能是2）
			// 如果是 0，left++ 后，i++，current 指向下一个位置。
			// 如果是 1，left++ 后，i++，current 指向下一个位置。
		} else if nums[i] == 2 {
			// 如果当前元素是 2，交换到数组的右边
			nums[i], nums[right] = nums[right], nums[i]
			// right 指针左移
			right--
			// 关键：因为从 right 换过来的元素 nums[i] 可能是 0, 1 或 2
			// 所以需要重新检查当前位置的元素，通过 i-- 来抵消 for 循环的 i++
			i--
		}
		// 如果 nums[i] == 1，则它已经在正确的位置（在0和2之间），i 直接在 for 循环中 ++ 即可
	}
}
// @lc code=end
```

### 方法比较

| 方面       | 双指针法 (荷兰国旗问题解法) | 计数排序法         |
| ---------- | ----------------------- | ----------------- |
| 时间复杂度 | $O(n)$                    | $O(n)$ (两次遍历) |
| 空间复杂度 | $O(1)$ (原地)             | $O(k)$ (k=3, 颜色数量) |
| 优点       | 原地排序，空间效率高     | 实现简单直观      |
| 缺点       | 逻辑稍复杂              | 需要额外空间      |
| 推荐度     | ★★★★★                   | ★★★★☆             |

**计数排序法思路：**
1. 遍历数组，统计 0, 1, 2 各自出现的次数。
2. 根据统计的次数，重写原数组。先写所有的 0，然后写所有的 1，最后写所有的 2。

这种方法也很简单，但题目要求原地排序，并且如果颜色种类很多，计数排序的空间复杂度会上升。对于本题，颜色只有三种，所以空间复杂度是 $O(1)$。

### 复杂度分析

**双指针法：**

-   **时间复杂度：** $O(n)$。
    `left` 和 `current` 指针从左向右移动，`right` 指针从右向左移动。每个元素最多被访问和交换常数次。`current` 指针最多遍历数组一次。
-   **空间复杂度：** $O(1)$。
    我们只使用了常数个额外的变量（`left`, `right`, `current`），是在原地修改数组。

### 关键收获

-   **双指针/三指针技巧**：是解决数组分区、排序问题的有效方法。荷兰国旗问题是其经典应用。
-   **原地操作**：理解如何通过交换元素来实现原地排序，节省空间。
-   **边界条件和指针移动逻辑**：在处理 `nums[i] == 2` 并交换后，`i--` 的细节处理非常重要，确保新换来的元素得到正确处理。如果 `nums[i] == 0`，`left` 和 `i` 都增加，因为 `left` 左边的元素已经是有序的 `0`，而 `i` 是从左边过来的，所以换到 `i` 位置的元素不可能是 `2`，只可能是 `0` 或 `1`。如果换过来的是 `0`，则 `i` 继续扫描，这个 `0` 会被正确处理；如果换过来的是 `1`，`i` 继续扫描，这个 `1` 也会被正确处理。

这道题是一个非常好的考察对数组操作和指针理解的题目。
