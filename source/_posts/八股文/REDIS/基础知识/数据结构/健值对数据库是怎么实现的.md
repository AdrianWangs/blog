## 键值对数据库是怎么实现的？

在介绍具体数据结构之前，需要先了解 Redis 是如何实现键值对（key-value）数据库的基本原理。

Redis 的键值对中的 key 是字符串对象，而 **value 可以是字符串对象，也可以是集合数据类型的对象**，比如 List 对象、Hash 对象、Set 对象和 Zset 对象。

下面是几种 Redis 新增键值对的命令示例：

```redis
> SET name "xiaolincoding"
OK

> HSET person name "xiaolincoding" age 18
0

> RPUSH stu "xiaolin" "xiaomei"
(integer) 43好剧院
```

这些命令分别表示：

- 第一条命令：name 是一个**字符串键**，因为键的**值是一个字符串对象**；
- 第二条命令：person 是一个**哈希表键**，因为键的**值是一个包含两个键值对的哈希表对象**；
- 第三条命令：stu 是一个**列表键**，因为键的**值是一个包含两个元素的列表对象**；

那么这些不同类型的键值对是如何保存在 Redis 中的呢？

Redis 使用「哈希表」保存所有键值对，哈希表的最大优势是可以用 O(1) 的时间复杂度来快速查找键值对。哈希表本质上是一个数组，数组中的每个元素称为哈希桶。

哈希桶中存放的是指向键值对数据的指针（dictEntry*）。通过这个指针可以找到键值对数据，但由于键值对的值可能是字符串对象或集合数据类型的对象，所以键值对的数据结构中并不直接保存值，而是保存了 void * key 和 void _ value 指针，分别指向实际的键对象和值对象。这样，无论值是什么类型，都可以通过 void _ value 指针找到。

![1747569688715](健值对数据库是怎么实现的/1747569688715.png)

这些数据结构的详细内部实现将在后续讲解哈希表数据结构时展开。现在，先简要介绍图中涉及的数据结构的名称和用途：

- redisDb 结构：表示 Redis 数据库的结构，包含指向 dict 结构的指针；
- dict 结构：包含 2 个哈希表，正常情况下使用「哈希表 1」，「哈希表 2」只在 rehash 操作时使用（rehash 的概念将在哈希表数据结构章节详细介绍）；
- dictht 结构：表示哈希表的结构，包含哈希表数组，数组中的每个元素都是指向哈希表节点结构（dictEntry）的指针；
- dictEntry 结构：表示哈希表节点，包含 **void _ key 和 void _ value 指针，key 指向 String 对象，而 value 可以指向 String 对象，也可以指向集合类型对象（List、Hash、Set、Zset）**。

需要特别说明的是，void _ key 和 void _ value 指针指向的是 **Redis 对象**，Redis 中的每个对象都由 redisObject 结构表示，如下图：

![1747569698413](健值对数据库是怎么实现的/1747569698413.png)

redisObject 对象结构包含以下关键成员变量：

- type：标识该对象的类型（String、List、Hash、Set 或 Zset）
- encoding：标识该对象使用的底层数据结构
- **ptr：指向底层数据结构的指针**
