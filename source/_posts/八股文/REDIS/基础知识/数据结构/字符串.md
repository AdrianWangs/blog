## 概述

字符串（String）是 Redis 中最基本、最常用的数据类型。Redis 字符串可以存储文本、整数或二进制数据，最大容量为 512MB。由于字符串类型的底层实现特点，使其在缓存、计数器、分布式锁等场景中有广泛应用。

## 核心概念

### 底层数据结构

Redis 的字符串是基于 SDS（Simple Dynamic String，简单动态字符串）实现的，而不是 C 语言中的字符串（以 \0 结尾的字符数组）。SDS 具有以下特点：

1. **二进制安全**：可以存储任何二进制数据，不受 \0 字符的限制
2. **动态扩容**：根据需要自动扩展空间
3. **惰性空间释放**：减少内存分配次数
4. **内置字符串长度**：获取字符串长度的时间复杂度为 O(1)
5. **缓冲区机制**：减少内存再分配操作

在 Redis 3.2 版本后，SDS 的定义如下：

```c
struct __attribute__ ((__packed__)) sdshdr8 {
    uint8_t len;        // 已使用长度
    uint8_t alloc;      // 分配的空间长度
    unsigned char flags; // 类型标志，sdshdr8表示为8
    char buf[];         // 字节数组，用于保存字符串
};
```

Redis 根据字符串长度，有不同的 SDS 结构体定义（sdshdr5、sdshdr8、sdshdr16、sdshdr32、sdshdr64），以优化内存使用。

### 编码方式

Redis 的字符串类型有三种编码方式：

1. **int**：当字符串值可以解释为 64 位有符号整数时使用
2. **embstr**：小于等于 44 字节的字符串使用嵌入式编码
3. **raw**：大于 44 字节的字符串使用普通编码

编码会根据操作和数据内容自动转换。

## 实现机制

### 动态扩容

当 SDS 需要追加内容导致空间不足时，会自动扩容：
- 如果扩展后长度小于 1MB，则分配的新空间为扩展后长度的两倍
- 如果扩展后长度大于等于 1MB，则分配的新空间为扩展后长度 + 1MB

这种策略既能减少内存重分配次数，又能避免过度浪费内存。

### 惰性空间释放

当 SDS 缩短字符串时，并不立即释放多余空间，而是记录下来，以便将来继续使用，避免频繁的内存分配。如果需要主动释放，可以使用 `sdsRemoveFreeSpace()` 函数。

### 整数优化

Redis 会识别字符串是否可以表示为整数，如果可以，会使用整数编码（int）存储，这样在进行数值操作时（如 INCR）可以直接进行整数运算，而无需先转换为字符串再解析。

## 使用方法

### 基本命令

```bash
# 设置键值
SET key value [EX seconds] [PX milliseconds] [NX|XX]
# 获取值
GET key
# 获取子串 (从 start 到 end 的内容)
GETRANGE key start end
# 设置子串 (在指定位置插入内容)
SETRANGE key offset value
# 获取旧值并设置新值
GETSET key value
# 获取值长度
STRLEN key
# 追加内容
APPEND key value
```

### 计数命令

```bash
# 递增 1
INCR key
# 递减 1
DECR key
# 递增指定整数
INCRBY key increment
# 递减指定整数
DECRBY key decrement
# 递增浮点数
INCRBYFLOAT key increment
```

### 批量操作

```bash
# 批量设置
MSET key1 value1 key2 value2 ...
# 批量设置(当且仅当所有键都不存在)
MSETNX key1 value1 key2 value2 ...
# 批量获取
MGET key1 key2 ...
```

### 示例

```bash
# 基本字符串操作
SET user:name "张三"
GET user:name  # 返回: "张三"
APPEND user:name "先生"
GET user:name  # 返回: "张三先生"
STRLEN user:name  # 返回: 9 (UTF-8编码，每个中文字符占3字节)

# 计数器示例
SET counter 10
INCR counter  # 返回: 11
INCRBY counter 5  # 返回: 16
DECR counter  # 返回: 15

# 位操作示例
SETBIT online:users 10086 1  # 设置用户 10086 在线
GETBIT online:users 10086  # 返回: 1，表示用户在线
BITCOUNT online:users  # 返回在线用户数
```

## 应用场景

### 缓存

字符串是最简单高效的缓存方式，可用于缓存各类数据：

```java
// 使用Jedis客户端示例
Jedis jedis = new Jedis("localhost");
// 缓存用户信息
jedis.set("user:1001", "{\"name\":\"张三\",\"age\":28}");
// 设置过期时间
jedis.expire("user:1001", 3600); // 1小时
```

### 计数器

由于字符串可以存储整数，并且提供了原子递增/递减操作，非常适合计数场景：

```java
// 页面访问计数
jedis.incr("page:views:index");
// 限流计数
String key = "rate:limit:" + userId;
jedis.incr(key);
jedis.expire(key, 60); // 60秒过期
long count = Long.parseLong(jedis.get(key));
if(count > 10) {
    // 超过限制
}
```

### 分布式锁

利用 SET 命令的 NX 选项和过期时间，可以实现简单的分布式锁：

```java
// 获取锁
String result = jedis.set("lock:resource", "requestId", 
                         SetParams.setParams().nx().ex(10));
if ("OK".equals(result)) {
    try {
        // 获取锁成功，执行业务操作
    } finally {
        // 释放锁，这里应该使用Lua脚本保证原子性
        String script = "if redis.call('get', KEYS[1]) == ARGV[1] then "
                      + "return redis.call('del', KEYS[1]) else return 0 end";
        jedis.eval(script, 
                  Collections.singletonList("lock:resource"),
                  Collections.singletonList("requestId"));
    }
}
```

### 共享Session

分布式系统中使用 Redis 字符串存储 Session：

```java
// 存储会话
String sessionId = generateSessionId();
jedis.setex("session:" + sessionId, 1800, serializeSession(sessionData));
// 响应中设置cookie
response.addCookie(new Cookie("JSESSIONID", sessionId));
```

### 缓存对象

使用 JSON 字符串缓存完整对象：

```java
// 序列化对象到Redis
ObjectMapper mapper = new ObjectMapper();
User user = getUserFromDb(userId);
jedis.setex("user:" + userId, 3600, mapper.writeValueAsString(user));

// 从Redis获取对象
String json = jedis.get("user:" + userId);
if (json != null) {
    User user = mapper.readValue(json, User.class);
    return user;
}
```

## 常见问题与解决方案

### 缓存穿透

**问题**：查询不存在的数据，每次都穿透到数据库
**解决**：
1. 对空值也缓存
   ```java
   String value = jedis.get(key);
   if (value == null) {
       // 从数据库查询
       String result = queryFromDb(key);
       // 无论是否为空，都缓存
       jedis.setex(key, 300, result == null ? "NIL" : result);
   }
   ```
2. 布隆过滤器预过滤

### 内存占用优化

**问题**：字符串过大导致内存占用过高
**解决**：
1. 使用压缩算法
   ```java
   // 使用snappy压缩
   byte[] compressed = Snappy.compress(originalData);
   jedis.setex(key, 3600, Base64.getEncoder().encodeToString(compressed));
   ```
2. 存储关键字段而非完整对象
3. 设置合理的过期时间

### 大key问题

**问题**：单个key存储的数据量过大
**解决**：
1. 拆分为多个key
   ```java
   // 将大字符串拆分
   String bigValue = getBigValue();
   int chunkSize = 1024 * 1024; // 1MB一个分片
   for (int i = 0; i < bigValue.length(); i += chunkSize) {
       int end = Math.min(i + chunkSize, bigValue.length());
       String chunk = bigValue.substring(i, end);
       jedis.setex(key + ":" + i, 3600, chunk);
   }
   ```
2. 考虑使用其他数据结构（Hash等）

## 最佳实践

1. **设置过期时间**：几乎所有的字符串都应该设置过期时间，防止内存持续增长
   ```java
   // 使用setex替代set+expire，保证原子性
   jedis.setex(key, seconds, value);
   ```

2. **批量操作**：优先使用批量命令，减少网络往返
   ```java
   // 使用mget替代多次get
   List<String> values = jedis.mget("key1", "key2", "key3");
   ```

3. **字符串长度控制**：控制在10KB以内，大对象考虑压缩或拆分

4. **数值操作优化**：
   ```java
   // 使用原子操作而非get+set模式
   // 不推荐
   int count = Integer.parseInt(jedis.get("counter")) + 1;
   jedis.set("counter", String.valueOf(count));
   
   // 推荐
   jedis.incr("counter");
   ```

5. **合理使用序列化格式**：JSON易读但占空间，考虑使用Protobuf等更紧凑的序列化格式

## 面试要点

1. Redis字符串与C字符串区别？
   - Redis使用SDS（简单动态字符串）
   - 二进制安全，可存储任意二进制数据
   - O(1)时间复杂度获取长度
   - 预分配空间和惰性空间释放，减少内存操作

2. Redis字符串的三种编码方式？
   - int：整数编码
   - embstr：短字符串优化编码
   - raw：长字符串标准编码

3. Redis的字符串为什么高效？
   - 动态扩容策略减少内存分配
   - 数值优化，整数直接操作
   - 原子操作，无需加锁
