# 博客文章创建与发布工作流

本工作流旨在提供一个清晰、高效的指南，帮助您完成从构思到发布的整个博客文章创建过程。它整合了项目中的自动化特性和内容规范。

## 1. 准备阶段

### 1.1. 确定文章主题与类型

- **主题选择**：选择您想要分享的知识、经验或见解。
- **类型定位**：根据内容确定文章类型，例如：
  - [通用文章](mdc:hexo-blog/.cursor/rules/content/generic-article-template.mdc)
  - [技术面试文章（八股文）](mdc:hexo-blog/.cursor/rules/content/technical-article-template.mdc)
  - [算法题解文章](mdc:hexo-blog/.cursor/rules/content/algorithm-post-template.mdc)
  - [Redis 相关文章](mdc:hexo-blog/.cursor/rules/content/redis-post-template.mdc)
  - [系统设计文章](mdc:hexo-blog/.cursor/rules/content/system-design-post-template.mdc)
  - [幂等性专题文章](mdc:hexo-blog/.cursor/rules/content/idempotency-article-template.mdc)

### 1.2. 查阅相关模板和指南

- 仔细阅读所选文章类型对应的模板和内容指南，确保了解所有要求。
- 特别注意：
  - [数学公式展示指南](mdc:hexo-blog/.cursor/rules/content/math-formula-guide.mdc)（如适用）
  - [时间工具使用指南](mdc:hexo-blog/.cursor/rules/blog/time-tools-usage.mdc)

## 2. 创建文章文件

### 2.1. 手动创建 Markdown 文件

- 在 `source/_posts/` 目录下的相应子目录中创建新的 `.md` 文件。
- **命名规范**：
  - 通用文章：`YYYY-MM-DD-文章标题.md`
  - 算法题解：`LeetCode-xxx-问题标题.md`
  - 技术八股文：`YYYY-MM-DD-技术八股-主题标题.md`
  - 其他类型文章请参考其特定指南或保持一致性。

> **注意**：根据 [博客自动化规则](mdc:hexo-blog/.cursor/rules/blog/blog-automation.mdc)，您不需要在本地使用 `hexo new` 命令，因为构建和部署由 GitHub Actions 自动处理。直接创建文件即可。

## 3. 编写 Front Matter

这是文章元数据配置的关键部分，请务必仔细填写。

```yaml
---
title: '您的文章标题'
date: YYYY-MM-DD HH:MM:SS # ⚠️ 必须使用 time-mcp 工具获取当前网络时间
categories:
  - 主分类
  - 子分类 (可选)
tags:
  - 标签1
  - 标签2
  - 相关技术标签 (例如: LeetCode, MySQL, Redis, 系统设计)
description: '文章内容的简明摘要 (150-200 字符)。此字段为必填项。'
# 根据文章类型模板，可能还有其他特定字段，例如：
# thumbnail: "/images/path-to-thumbnail.jpg" (通用文章)
# 难度: Easy/Medium/Hard (算法文章)
---
```

### 3.1. 关键字段说明：

- `title`: 文章的标题。
- `date`: 文章的发布日期和时间。**必须**使用 `time-mcp` 工具获取当前网络时间，格式为 `YYYY-MM-DD HH:MM:SS`。请参考 [时间工具使用指南](mdc:hexo-blog/.cursor/rules/blog/time-tools-usage.mdc)。
  ```xml
  <use_mcp_tool>
  <server_name>time-mcp</server_name>
  <tool_name>current_time</tool_name>
  <arguments>
  {
    "format": "YYYY-MM-DD HH:mm:ss"
  }
  </arguments>
  </use_mcp_tool>
  ```
- `categories`: 文章所属分类，可以有多级。
- `tags`: 文章标签，便于检索和关联。
- `description`: 文章摘要，**必填**，长度控制在 150-200 字符。

## 4. 撰写文章内容

- 遵循所选文章类型模板的结构（例如：引言、核心概念、代码实现、总结等）。
- **内容质量**：确保内容准确、深入且具有实用性。
- **格式规范**：
  - 使用 Markdown 语法。
  - 若包含数学公式，请遵循 [数学公式展示指南](mdc:hexo-blog/.cursor/rules/content/math-formula-guide.mdc)。
- **图片管理**：
  - 如果文章包含图片，建议将图片存放在与文章 `.md` 文件同名的子目录中。
  - 在文章中使用相对路径引用图片，例如：`![图片描述](文章同名目录/图片文件名.png)`。

## 5. 更新相关索引/目录 (如适用)

对于特定类型的文章，创建或更新后，需要手动更新其对应的目录索引页面：

- **算法文章**: 更新 [算法目录](mdc:hexo-blog/source/algorithms/index.md)。参考 [算法目录管理指南](mdc:hexo-blog/.cursor/rules/content/algorithm-directory.mdc)。
- **MySQL 文章**: 更新 [MySQL 知识体系](mdc:hexo-blog/source/mysql/index.md)。参考 [MySQL 目录管理指南](mdc:hexo-blog/.cursor/rules/content/mysql-directory.mdc)。
- **Redis 文章**: 更新 [Redis 知识体系](mdc:hexo-blog/source/redis/index.md)。参考 [Redis 目录管理指南](mdc:hexo-blog/.cursor/rules/content/redis-directory.mdc) 和 [Redis 目录更新提醒](mdc:hexo-blog/.cursor/rules/content/redis-directory-update-reminder.mdc)。
- **系统设计文章**: 更新 [系统设计知识体系](mdc:hexo-blog/source/system-design/index.md)。参考 [系统设计目录管理指南](mdc:hexo-blog/.cursor/rules/content/system-design-directory.mdc)。

## 6. 本地预览 (可选但推荐)

虽然最终部署由 GitHub Actions 完成，但本地预览可以帮助您检查文章的渲染效果和内容准确性。

- 打开终端，导航到博客根目录。
- 运行 `hexo clean && hexo server` 或 `hexo s`。
- 在浏览器中打开 `http://localhost:4000` 查看。

## 7. 提交与推送

这是将您的文章发布到线上的关键步骤。

- **检查状态**:
  ```bash
  git status
  ```
- **添加更改**:
  ```bash
  git add .
  ```
- **提交更改**: 使用描述性的提交信息。
  ```bash
  git commit -m "feat: 添加新文章《[您的文章标题]》"
  # 或者 "fix: 修改文章《[您的文章标题]》的xxx部分"
  # 或者 "docs: 更新[算法/MySQL/Redis]目录"
  ```
- **推送到远程仓库**:
  ```bash
  git push origin main
  ```
  参考 [Git 工作流指南](mdc:hexo-blog/.cursor/rules/development/git-workflow.mdc) 和 [博客自动化指南](mdc:hexo-blog/.cursor/rules/blog/blog-automation.mdc)。

## 8. 检查 GitHub Actions

- 推送后，GitHub Actions 会自动开始构建和部署您的博客。
- 您可以在 GitHub 仓库的 "Actions" 标签页查看构建状态和日志。
- 确保工作流成功完成。

## 9. 验证线上效果

- GitHub Actions 成功部署后，访问您的博客线上地址 (例如: `https://adrianwangs.github.io/`)。
- 检查新文章是否已正确发布，排版、图片、链接等是否正常。

---

遵循此工作流，您可以更规范、高效地管理和发布您的博客内容。
